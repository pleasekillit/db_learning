# 阶段 1 · SQL 实操通关

> 本阶段在 SQLite 命令行里手写 SQL，把「概念」变成「能查数」。
> 这是直接能用在看板、历史对比、AI 取数上的基本功，务必练到位。

## 本章目标
- 熟练 DDL（建表）、DML（增删改）、DQL（查）。
- 会用 JOIN 联多表、GROUP BY 聚合、ORDER BY/LIMIT 排序分页。
- 知道索引是干嘛的，能用 `EXPLAIN` 看执行计划。

## 对应代码位置

骨架里的 `models/*.py` 就是「程序化的建表语句」——每个 `mapped_column` 对应 `CREATE TABLE` 里的一列。
本阶段你手写的 `CREATE TABLE` 和这些表是一一对应的：

| 你在 SQL 里写的 | 对应代码里的 |
| --- | --- |
| `CREATE TABLE samples (...)` | `powerdb/models/project.py` 中的 `Sample` |
| `CREATE TABLE test_runs (...)` | `powerdb/models/test_run.py` 中的 `TestRun` |
| `CREATE TABLE measurements (...)` | `powerdb/models/result.py` 中的 `Measurement` |
| 外键 `REFERENCES samples(id)` | `ForeignKey("samples.id")` |
| 索引 `CREATE INDEX ...` | `mapped_column(..., index=True)` |

> 建议本阶段对照 `models/` 里的字段类型（`String`/`Float`/`Integer`/`DateTime`）来写建表 SQL，
> 加深「SQL 类型 ↔ Python 类型」的对应记忆。

## 基础知识详解

### 0. 标准 SQL 与 SQLite 方言对照（分清「必学」与「用到再查」）

SQL 有统一的 ANSI/ISO 标准，主流数据库（SQLite / MySQL / PostgreSQL / SQL Server）都实现它的主干，
但各有方言扩展。下面把本章出现的每一句语法，标注清楚哪些是「标准 SQL（各库通用、必学）」、
哪些是「SQLite 方言（换库要改、用到再查）」。

| 本章语法 | 类别 | 换 PostgreSQL 时会变成 |
| --- | --- | --- |
| `SELECT / FROM / WHERE / ORDER BY / LIMIT` | 标准 SQL | 通用。`LIMIT` 多数库通用，SQL Server 写成 `TOP` |
| `INSERT / UPDATE / DELETE` | 标准 SQL | 通用 |
| `CREATE TABLE`、`CREATE INDEX` | 标准 SQL | 通用 |
| `PRIMARY KEY`、`UNIQUE`、`NOT NULL`、`REFERENCES`（外键） | 标准 SQL | 通用 |
| `JOIN ... ON`（INNER / LEFT） | 标准 SQL | 通用 |
| `GROUP BY` + `COUNT / AVG / MIN / MAX / SUM` | 标准 SQL | 通用 |
| `AS`（列别名）、`DESC`（倒序） | 标准 SQL | 通用 |
| `AUTOINCREMENT` | **SQLite 方言** | PG 用 `SERIAL` / `IDENTITY`，MySQL 用 `AUTO_INCREMENT` |
| `INTEGER / REAL / TEXT` 类型名 | **SQLite 方言** | PG 用 `integer / numeric / text`（类型体系不同） |
| `PRAGMA foreign_keys=ON` | **SQLite 方言** | PG 默认开外键，无需 `PRAGMA` |
| `EXPLAIN QUERY PLAN` | **SQLite 方言** | PG 用 `EXPLAIN ANALYZE` |

**学习优先级建议**：
- 「标准 SQL」那几行 = **必学**，要能看懂、能写出来（对应下面第 1~6 小节里的主干语法）；
- 「SQLite 方言」那几行 = **用到再查**，不必背。将来换 PostgreSQL 时，SQLAlchemy（03 章起）
  会自动生成对应方言的写法——这也是 ORM/Core 帮你屏蔽方言差异的核心价值。

### 1. DDL：建表
```sql
CREATE TABLE samples (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id  INTEGER NOT NULL REFERENCES projects(id),
    code        TEXT    NOT NULL UNIQUE,
    name        TEXT    NOT NULL,
    model       TEXT
);
CREATE INDEX ix_samples_project_id ON samples(project_id);
```

### 2. DML：增删改
```sql
INSERT INTO samples (project_id, code, name, model) VALUES (1, 'S-0001', '样品A', 'PCS-100');
UPDATE samples SET model = 'PCS-200' WHERE code = 'S-0001';
DELETE FROM samples WHERE code = 'S-0001';
```

### 3. DQL：查（本阶段重点）
```sql
SELECT * FROM samples;
SELECT name, model FROM samples WHERE project_id = 1;
SELECT metric, value, unit FROM measurements WHERE value > 95.0;
```

### 4. JOIN：联表
```sql
-- 把「批次号 + 样品名 + 测试项名 + 指标值」连出来
SELECT tr.run_no, s.name AS sample, si.name AS item, m.value, m.unit
FROM measurements m
JOIN test_records r  ON m.test_record_id  = r.id
JOIN test_runs tr    ON r.test_run_id     = tr.id
JOIN samples s       ON tr.sample_id      = s.id
JOIN standard_items si ON r.standard_item_id = si.id
WHERE m.metric = 'efficiency'
ORDER BY tr.started_at DESC
LIMIT 10;
```
> 初学记住：`JOIN ... ON 外键 = 主键`。INNER JOIN 只保留两边都匹配的行，LEFT JOIN 保留左表全部。

### 5. GROUP BY + 聚合
```sql
SELECT s.name, AVG(m.value) AS avg_eff, COUNT(*) AS n
FROM measurements m
JOIN test_records r ON m.test_record_id = r.id
JOIN test_runs tr   ON r.test_run_id    = tr.id
JOIN samples s      ON tr.sample_id     = s.id
WHERE m.metric = 'efficiency'
GROUP BY s.name;
```

### 6. 索引与执行计划
```sql
CREATE INDEX ix_measurements_metric ON measurements(metric);
EXPLAIN QUERY PLAN SELECT * FROM measurements WHERE metric = 'efficiency';
```
- 索引 = 目录，加快按某列查找，但会拖慢写入、占空间，别乱加。
- 给 WHERE / JOIN / ORDER BY 常出现的列建索引最划算。

## 训练 Demo 详解

**准备**：启动 sqlite3 命令行（DBeaver 图形化也可以）：
```bash
# 在任意目录
sqlite3 demo.db
```

**任务**：建 3 张表（samples / test_runs / measurements），插入 3 批测试数据，写出并跑通这 5 条查询：
1. 查某样品所有批次；
2. 查某测试项的历史效率值并排序；
3. 按样品分组算效率均值；
4. 联表查出「批次号 + 样品名 + 测试项名 + 指标值」；
5. 给 `measurements.metric` 加索引，`EXPLAIN` 对比加索引前后。

**建议**：也可以把 `powerdb/models/` 里 9 张表的建表 SQL 全部手写一遍，建出一套完整 schema。

**验证标准**：闭卷写出含 JOIN + GROUP BY 的一条多表查询。
