# 阶段 10 · 端到端完整案例：从业务需求到 Excel 导出

> 把前面所有章节串成一条主线：**一条真实业务需求，如何经历"数据库设计 → 分层代码实现 →
> 判定逻辑 → Excel 导出"四个环节，最后变成业务看得懂的交付物。**
>
> 可运行脚本：[end_to_end_case.py](../powerdb/examples/end_to_end_case.py)

## 业务需求（一句话）

> 型号 PCS-100 储能逆变器依据国标 GB/T 34120 送审，硬性限值：
> **额定效率 ≥ 95%、总谐波失真 ≤ 5%、温升 ≤ 60℃**。
> 现有 3 台样机、多批次实测数据，需要**自动判定哪些批次不合格**，并**给评审一份 Excel 报告**。

## 第 1 步：数据库设计（把业务语句拆成实体）

业务语句里的名词 → 实体，动词 → 关系，"一层对多一层"：

| 实体（表） | 关键字段 | 说明 |
| --- | --- | --- |
| `projects` | name | 项目/产品线 |
| `samples` | code / model | 样机（被测对象） |
| `standards` | code / category | 标准本体（国标） |
| `standard_items` | code / name / **limit_min / limit_max** | 测试项 + 判定阈值 |
| `test_runs` | run_no / started_at | 一次试验批次 |
| `test_records` | status / started_at | 一个测试项的一次记录 |
| `measurements` | metric / value / unit | 标量结果（`metric` 是数据不是列） |
| `data_files` | name / path / kind | 相关数据文件 |

**关键设计决策**（体现"表格设计与数据库设计不割裂"）：
- 指标名 `metric` 用字符串存，**新增指标不改表**；
- 判定阈值 `limit_min / limit_max` 落在 `standard_items`，判定规则本身不落库，由 service 层现算。

## 第 2 步：代码实现（分层各司其职）

| 层 | 职责 | 本案例对应文件 |
| --- | --- | --- |
| models | 声明表结构（= 数据库设计落地） | `models/project.py`、`models/standard.py`、`models/test_run.py`、`models/result.py`、`models/data_file.py` |
| repositories | 复杂 JOIN 查询 | `repositories/result_repository.py::query_for_comparison` |
| services | 业务规则（判定） | `services/comparison_service.py::judge_metric` |
| schemas | 边界校验/序列化 | `schemas/result_schema.py` |
| exporters | 面向业务的交付 | `exporters/excel_exporter.py` |

## 第 3 步：判定逻辑（一条业务规则）

`judge_metric(metric, standard_item_id=...)` 做三件事：
1. 用 `compare_metric` 取出该指标所有批次的历史值；
2. 用 `standard_item_id` 查到该测试项的 `limit_min / limit_max`；
3. 逐行判定：低于下限或高于上限 → `不合格`；无数值/无阈值 → `未判`；否则 `合格`。

```python
from powerdb.services.comparison_service import judge_metric

rows = judge_metric("efficiency", standard_item_id=eff_id)
# [{'run_no': 'R-003', 'sample_code': 'S-1003', 'value': 94.1,
#   'limit_min': 95.0, 'limit_max': 100.0, 'verdict': '不合格'}, ...]
```

## 第 4 步：Excel 导出（业务交付）

两份报告：
- **判定结果表**：`export_judge_table()` —— 中文表头（试验编号/样品编号/测试项/测量值/单位/下限/上限/判定），
  **不合格行标红、合格行标绿**，冻结首行。字段映射在 `field_map.JUDGE_FIELDS`。
- **用例执行记录表**：`export_case_records_to_excel()` —— 覆盖用例编号/名称/执行时间/结果/相关数据文件。

## 训练 Demo 详解

**运行**（项目根目录 `/workspace/powerdb` 下）：
```bash
python examples/end_to_end_case.py
```

输出会依次打印四步，最后给出"给业务的话"：
```
  · 额定效率：共 6 批，1 批不合格 -> R-003(94.1)
  · 总谐波失真：共 5 批，1 批不合格 -> R-005(5.6)
  · 温升：共 4 批，1 批不合格 -> R-004(62.0)
```
并生成 `exports/11_判定结果.xlsx`、`exports/11_用例执行记录.xlsx`。

**进阶练习**：
- 把 `RUNS` 换成你真实项目的送审数据，跑一遍就是你的专属送审报告生成器；
- 在 `standard_items` 里补一个「双阈值」指标（既有下限又有上限），观察判定逻辑自动兼容；
- 把判定结果和用例记录合成**一个 Excel 两个 Sheet**，体验"一份完整报告"的呈现。
