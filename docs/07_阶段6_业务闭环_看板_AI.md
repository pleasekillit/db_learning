# 阶段 6 · 业务闭环：横向对比 / 看板 / AI 接口

> 把前面攒的能力，对外暴露成三类稳定接口，让数据库真正服务业务。
> 核心思想：**一处业务逻辑（Service 层），多个消费方（看板/AI/API）**。

## 本章目标
- 用 `comparison_service` 实现跨批次历史横向对比。
- 设计只读接口（REST/FastAPI）给前端看板用。
- 为 AI 分析导出「稳定 schema 快照 + 时序切片 + 原始波形通道」。

## 对应代码位置

| 内容 | 对应代码 |
| --- | --- |
| 横向对比查询 | `powerdb/repositories/result_repository.py` 的 `query_for_comparison()` |
| 统计聚合 | `powerdb/services/comparison_service.py` 的 `summarize_metric()` |
| 时序读取/降采样 | `powerdb/services/timeseries_service.py` 的 `read_channel()` / `resample()` / `to_dataframe()` |
| 边界出参契约 | `powerdb/schemas/*.py` 的 `...Out` / `ComparisonRow` |
| 演示 | `examples/seed_demo.py`（已含横向对比 + 概要统计） |

## 基础知识详解

### 1. 为什么「同源三出口」
不要为看板、AI、对比各自写一套 SQL。所有核心查询都在 `services/`，
三个出口各取所需：
- **看板**：`summarize_metric()` 返回 min/max/avg/std/count，画趋势/分布。
- **横向对比**：`compare_metric(metric, as_dataframe=True)` 返回 DataFrame。
- **AI**：`MeasurementOut` / `ComparisonRow` 等 Pydantic 模型保证结构稳定。

### 2. 面向 AI 的三类接口
1. **稳定数据快照**：一次试验的元数据 + 标量 + 降采样时序，导出固定 JSON。
2. **可切片检索**：`query_for_comparison` / `get_channel_points` 支持按时间/样品/指标切片。
3. **原始波形通道**：`raw_path` 指向 Parquet，AI 直接读大数据，不必查库。

### 3. 看板只读接口（FastAPI 示例）
```python
from fastapi import FastAPI
from powerdb.services import comparison_service as cs

app = FastAPI()

@app.get("/metrics/{metric}/summary")
def metric_summary(metric: str):
    return cs.summarize_metric(metric)

@app.get("/metrics/{metric}/series")
def metric_series(metric: str):
    return cs.compare_metric(metric)   # 看板直接画时序散点/趋势
```

### 4. 出参契约（Pydantic）
```python
class ComparisonRow(BaseModel):
    sample_code: str
    run_no: str
    item_name: str
    value: Optional[float]
    unit: Optional[str]
    started_at: Optional[datetime]
```
稳定的 schema = 大模型/前端/API 的「接口文档」，字段一变能立刻被类型系统发现。

## 训练 Demo 详解

**任务一（横向对比）**：跑 `examples/seed_demo.py`，已经打印出两组样品效率对比和概要统计：
```
横向对比 efficiency：
  S-0001 / RUN-2026-001 / 额定效率: 97.2%
  S-0002 / RUN-2026-002 / 额定效率: 96.1%
概要统计： {'metric': 'efficiency', 'count': 2, 'min': 96.1, 'max': 97.2, 'mean': 96.65, 'std': ...}
```

**任务二（时序切片）**：用 `read_channel` / `resample` 把 1000 点通道降采样到看板可绘尺度。

**任务三（看板接口）**：装 `fastapi`+`uvicorn`，把上面两个 endpoint 跑起来，用浏览器/curl 验证返回 JSON。

**任务四（AI 快照）**：设计并实现一个 `dump_snapshot(run_id)`，导出固定 JSON，作为后续接大模型的入口。

**验证标准**：看板能展示跨批次趋势；AI 能拿到稳定结构化数据而不必懂你的表结构。
